# TEMPLATE 1 VISUAL DESIGN BLUEPRINT

Scope:
- Visual design blueprint for `fastwork_inspired`.
- No CMS changes.
- No architecture changes.
- No code changes.
- This document defines the visual direction of Template 1 in a form that can be translated into UI work directly.

## 1. Overall Visual Direction

Template 1 must feel like:
- a commercial SaaS product website
- not an admin dashboard
- not a wireframe
- not a generic landing page

The design language should combine:
- product realism
- commercial clarity
- operational trust
- modern SaaS density

The page must look closer to:
- HubSpot
- Fastwork
- Getfly
- Monday
- Bitrix24

than to:
- a CMS demo
- an admin form
- a plain card grid

## 2. Color Direction

### Primary palette
- Main accent: deep blue
- Support accent: lighter blue
- Neutral background: very light slate / off-white
- Surface: white with soft depth
- Text: dark slate / near-black

### Color behavior
- Primary CTA uses the strongest accent color.
- Featured pricing uses a controlled accent tint.
- Trust and security use calm neutral cards, not saturated colors.
- Badges should use small accent fills, not full-width color blocks.

### Avoid
- flat monotone white surfaces
- decorative gradients with no product meaning
- overly bright or playful colors

## 3. Typography Direction

### Hierarchy
- Hero headline: large, bold, commercial
- Section heading: strong but smaller than hero
- Card title: clear and readable
- Body text: compact, scannable
- Meta / badge text: small and structured

### Feel
- Confident
- Compact
- Business-oriented
- Modern

### Rules
- Headlines should not stretch too wide.
- Body text should not become paragraph-heavy.
- Keep line lengths controlled for easy scanning.

## 4. Card System

### Card style
- Light surface
- Soft shadow
- Clear border or depth separation
- Consistent radius
- Mild hover lift

### Card hierarchy
1. Hero canvas panels
2. Product demo cards
3. Pricing cards
4. Marketplace cards
5. Security cards
6. Metrics cards

### Card behavior
- Cards should feel layered.
- Important cards should appear elevated.
- Secondary cards should remain simpler.

## 5. Hero Visual Design

### Layout
- 12-column grid
- Left: 5 columns
- Right: 7 columns
- Height: 720px to 820px

### Left side
- Badge
- Headline
- Subheadline
- Trust indicators
- Primary CTA
- Secondary CTA

### Right side: product canvas
- Large dashboard visual
- No plain card block
- No blank table
- No placeholder panels

### Product canvas composition
The hero canvas should combine:
- KPI strip
- revenue curve
- pipeline stages
- task panel
- activity feed
- customer list
- invoice summary

### Visual intent
- It must look like an operating product, not a mockup frame.
- It should have believable density.
- It should show enough detail to create instant product understanding.

## 6. CRM Showcase Visual Design

### Layout
- Left: CRM product screenshot
- Right: benefits + CTA

### CRM screenshot composition
- Pipeline lanes:
  - Lead
  - Qualified
  - Proposal
  - Won
  - Lost
- Deal cards with value
- Revenue block
- Recent activity block

### Visual treatment
- Use a dashboard surface.
- Use visible lanes and cards.
- Show movement and state, not just labels.

## 7. Inventory Showcase Visual Design

### Layout
- Larger product visual than text

### Inventory screen composition
- Warehouse summary cards
- Stock totals
- Low stock warning strip
- Movement list
- Inventory trend chart

### Visual treatment
- The inventory screen should feel operational.
- It should immediately read as inventory control software.

## 8. Invoice Showcase Visual Design

### Visual composition
- Billing dashboard surface
- Status totals:
  - Paid
  - Pending
  - Overdue
- Invoice table
- Revenue summary
- Collection summary

### Visual treatment
- Dense but readable.
- Strong status clarity.
- Clear numeric hierarchy.

## 9. Payment Showcase Visual Design

### Visual composition
- SePay-style operations console
- Transactions list
- Matched count
- Unmatched count
- Reconciliation summary
- Daily volume chart

### Visual treatment
- Emphasize operational flow.
- Reconciliation should be visible as a real working process.

## 10. Platform Explorer Visual Design

### Layout
- Tab bar across the top
- One main product visual area
- One KPI panel
- One workflow/benefit area

### Tabs
- CRM
- Inventory
- Invoice
- Payments
- Projects
- DMS

### Tab switching behavior
- Must update the screenshot.
- Must update KPI values.
- Must update workflow and benefits.

### Visual intent
- This must feel like a guided product tour.

## 11. Marketplace Visual Design

### Layout
- Mini app store card grid

### Card content
- Icon
- Category
- Badge
- Title
- Description
- CTA

### Visual treatment
- Each card should have enough depth to feel clickable.
- The grid should feel like an ecosystem, not a list.

## 12. Comparison Matrix Visual Design

### Structure
- KT SaaS on one side
- Fragmented solutions on the other side

### Rows
- CRM
- Inventory
- Invoice
- Payments
- Reporting
- Automation
- User Management

### Visual treatment
- KT SaaS should stand out with stronger checkmarks and highlighting.
- The comparison should be instantly scannable.

## 13. Security & Trust Visual Design

### Layout
- 6 cards in a 3x2 grid

### Cards
- Multi Tenant
- Backup
- Monitoring
- Audit Logs
- Access Control
- Payment Security

### Visual treatment
- Calm, clear, highly readable.
- Trust cards should feel stable and deliberate.

## 14. Pricing Visual Design

### Layout
- Multi-card pricing grid
- One featured plan

### Visual treatment
- Featured plan must be clearly taller, darker, or more emphasized.
- Modules and quota should be visually grouped.
- Add-ons should be scannable.

### CTA treatment
- Primary CTA must be visually dominant.
- Secondary CTA should remain available without competing with the primary CTA.

## 15. Social Proof Visual Design

### Preferred format
- Metrics band
- Not fake logos

### Cards
- Tenant Count
- Invoice Count
- Transaction Count
- Uptime
- API Calls

### Visual treatment
- Compact and credible.
- Numeric emphasis first.

## 16. CTA System Visual Design

### CTA styles
- Primary filled button
- Secondary outline button

### Placement
- Hero
- After CRM showcase
- After Marketplace
- After Pricing
- Footer

### Visual rule
- CTAs must feel like part of the sales flow, not random buttons.

## 17. Spacing / Rhythm

### Section rhythm
- Use consistent vertical spacing between sections.
- Keep the layout breathable but not empty.

### Inside sections
- Cards should have enough internal padding for readable density.
- Avoid excessive whitespace that weakens the product story.

## 18. Shadows / Depth

### Shadow levels
- Hero canvas: strongest depth
- Showcase cards: medium depth
- Marketplace / pricing cards: lighter depth
- Trust cards: restrained depth

### Goal
- Use depth to distinguish layers, not to decorate.

## 19. Responsive Visual Rules

### Desktop 1440
- Full 12-column behavior
- Product visuals dominate

### Laptop 1280
- Maintain composition
- Reduce density only where necessary

### Tablet 768
- Stack or compress hero
- Use 2-column marketplace
- Keep pricing readable
- Use scrollable tabs for explorer if needed

### Mobile 375
- Copy first
- Visual second
- Tabs become compact and scrollable
- Comparison matrix should not become unreadable

## 20. Implementation Order

1. Hero canvas
2. CRM showcase
3. Inventory showcase
4. Invoice showcase
5. Payment showcase
6. Platform explorer
7. Marketplace cards
8. Comparison matrix
9. Security & trust
10. Pricing emphasis
11. Social proof metrics
12. CTA system
13. Responsive refinements

## 21. Final Visual Target

The final page should feel:
- premium
- operational
- product-led
- commercially credible
- easy to scan

It should not feel like:
- a dashboard page
- an admin panel
- a CMS demo
- a placeholder landing
